# R-00352 P1-1 fix report — TimerManager::destroy_scope

## Status

Fixed in worktree `feat/r-00352-timer-manager`. Not pushed.

## Change

Public `destroy_scope` now leaves a tombstone (`alive = false`, last generation kept) instead of `scopes.remove`. `register_scope(same id)` bumps generation and does not wrap to 1. Old `TimerScope` is `scope_invalid` while destroyed and `scope_generation_mismatch` after reuse. Destroy reuses `teardown_scope` queue invalidation (`retire_scope_timers`) so queued firings drain as `late_completion`, not deliveries.
